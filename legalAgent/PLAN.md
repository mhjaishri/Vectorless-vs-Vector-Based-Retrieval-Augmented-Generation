# Legal AI Agent — Project Plan

## Goal
Build a RAG chat system over Indian law documents (Constitution of India, BNS, BNSS), evolving into a full legal AI agent.

## Current Phase: RAG Chat CLI
Vectorless RAG using PageIndex hierarchical tree indexing + TypeScript CLI.

---

## Architecture

### Two-Phase Design
**Phase 1 — Indexing (Python, one-time)**
- PageIndex generates a hierarchical tree from each PDF via LLM calls
- Tree nodes: `{ title, node_id, start_index, end_index, text?, nodes? }`
- Output: `indexes/constitution.tree.json`, `indexes/bns.tree.json`, `indexes/bnss.tree.json`

**Phase 2 — RAG Chat (TypeScript, hot path)**
```
User Query
  → HyDE: Tavily web search + hypothetical legal answer (gpt-4o-mini)
  → Enriched query (original + hypothesis)
  → Hierarchical tree search across all 3 docs in parallel (gpt-4o-mini)
      Level 1: pick relevant Parts/Chapters from skeleton
      Level 2+: recurse into children until leaf nodes
  → fetchNodeText() for matched nodes
  → generateResponse(originalQuery, results, history) → streamed answer (gpt-4o)
```

### Key Rules
- `enrichedQuery` used for retrieval, `userQuery` for final answer — never mix them
- `buildSkeleton()` called before every `navigateTree()` call — strips text to prevent context overflow
- Always search all 3 docs in parallel — no doc-routing LLM call
- `if_add_node_text: "yes"` is mandatory in indexing — default is `"no"`, silently breaks retrieval

| Future backend | Express |

## Setup & Run

### 1. Install dependencies
```bash
npm install

# Python (indexing only)
git clone https://github.com/VectifyAI/PageIndex /tmp/pageindex
pip install -r scripts/requirements.txt
```

### 2. Configure environment
```bash
cp .env.example .env
# Fill in: LLM_API_KEY (OpenAI key), TAVILY_API_KEY
```

### 3. Generate indexes (one-time, ~10-30 min per document)
```bash
python3 scripts/generate_index.py
```

### 4. Run the chat CLI
```bash
npx tsx src/index.ts
```

## Environment Variables
| Variable | Description | Default |
|----------|-------------|---------|
| `LLM_API_KEY` | OpenAI API key | — |
| `LLM_BASE_URL` | Override base URL (leave blank for OpenAI) | — |
| `NAV_MODEL` | Model for tree navigation + HyDE | `gpt-4.1-mini` |
| `ANSWER_MODEL` | Model for final answer generation | `gpt-4.1` |
| `TAVILY_API_KEY` | Tavily search API key | — |

**To use Gemini instead of OpenAI:**
```
LLM_API_KEY=<gemini-key>
LLM_BASE_URL=https://generativelanguage.googleapis.com/openai/
NAV_MODEL=gemini/gemini-2.0-flash
ANSWER_MODEL=gemini/gemini-2.5-pro
```

## Decisions & Rationale
| Decision | Reason |
|----------|--------|
| PageIndex over vector RAG | Preserves legal document hierarchy; no embedding costs |
| Always search all 3 docs | Cross-doc queries (e.g. "rights of accused") span all 3; routing LLM adds cost + misroutes |
| gpt-4o-mini for navigation | Classification task (pick node_ids); ~30x cheaper than gpt-4o |
| HyDE with Tavily | Enriches query with legal terminology before tree navigation, improving precision |
| Trees in memory | Static JSON, loaded once at startup; no DB needed at this stage |
